--- layout: layout.html title: Entrants description: "Add and manage the entrants in a tournament." extraScripts: - /scripts/tournament-manage.js --- {% comment %} The screen a tournament is run from. Search, add, mark paid, confirm, seed, randomise. Everything on it is one call each: tdc_tournament_entrants to read the list, and tdc_add_entrant / tdc_set_entrant / tdc_remove_entrant / tdc_set_seeds to change it. After every write the list is read again rather than patched here, because the server owns the ordering. Reached as /tournaments/manage/?t=. {% endcomment %}

Entrants

{% comment %} How people get in. Three settings, which is the whole of the entry design: who may put themselves down, and whether the TD's own criterion for confirming somebody is payment. These stay changeable for as long as the tournament is taking entries, unlike the draw settings on the bracket page — a TD who opens entries and then decides to close them early is an ordinary thing to do. {% endcomment %}

How people get in

Ticking somebody as paid confirms them too. Leave this off if you confirm on something other than payment.
Entering needs an account with a confirmed email address.
{% comment %} The poster. Nothing about a tournament is readable by anybody outside the app until a poster is generated and shared — and the two are separate acts, so a TD can build one, read the text out of it for a designer, and never make it public. What goes in is the TD's choice. The default is the tournament and the entrant counts; names and the draw are opt-in, because the real entrant list is the TD's. {% endcomment %}

{% comment %} Who runs it. A tournament always has a director — whoever created it — and may have referees and scorers. This matters more than it looks: score_entry_mode can be set to 'referee' or 'scorer', and without a way to appoint one the tournament would have nobody able to score it. The role list comes from tbl_competition_role_types rather than being written out here, because that table is a lookup with a rank for exactly this reason — a new role should not need a page edit. {% endcomment %}
