### Styling

Loaded in this order by `_includes/layout.html`, each with `?v={{ build.version }}`:

`variables.css` → `global.css` → `nav.css` → `forms.css` → `controls.css` → `status.css` → `dots.css` → `loader.css` → `footer.css` (unless `hideFooter`) → `design.css` → then the page's own.

### The design (UV, 7 Nov: the whole site but the match stage)

The neumorphism sandbox's design is the site's. **Everything is see-through and only shadows draw it**, cast by the light, which moves all round the screen just outside it (`page-light.js`; its glow is off). Raised: cards (`--nm-card`), buttons, things you press to open. Sunken: inputs, panels, tracks, wells. The card floats above its inputs; something level with the card casts no shadow onto it.

| Rule | Value |
|---|---|
| Text | 16px for values, row labels and body; 0.85rem secondary; no small capitals |
| Field height | 52px (`--nm-field`): fields, buttons, toggles, tabs, number inputs |
| Between fields | 24px; words start `--nm-pad` in from the edge; one right edge |
| Filters and names (UV, 9 Nov) | A filter's field takes `.drop-joined`: a small pill holding the grey label and then the selection, in one row where filters fit. A form's dropdowns keep the label beside a pill round the selection. A team's name is `--color-team` (the edited blue): a new place joins the list in `design.css` or takes `.team-name`. `--color-success` is now a soft orange, `#ff9b61`, not a green |
| Icons | **No rings round icons or pictures** (`.ring` hidden outside the stage). A player's or venue's picture is a circle, a league's a shield, a team's a hexagon, each set into the page (see below) |
| Selected | See-through with an inner glow (`--nm-knob-glow`). `.btn-primary` is the only solid green |
| Motion | A glow or selection that moves is always animated: on its own layer with `opacity`, or `outline-color`. **Never a transition on a box-shadow holding a `--nm-*` value**: the light rewrites it every 66ms and restarts it |
| Long lists | One sunken panel holds the rows, with hairlines: every shadow repaints as the light moves |

**Controls** (`tdc-controls.js`; each stays the real element, so a page reads `.value` and hears `change` as before): a `<select>` is the dropdown, a sunken pill that is a window on its words and pushes what is under it down; a number is a sideways stepper that thins at either end once the pointer has left it; a date is the browser's own field in a pill; a checkbox is a see-through knob glowing inward, a tick in a sunken well for `data-control="ring"`. Tabs (`.league-nav`) mark the chosen one with a thumb that slides.

**Pictures are set into the page (UV, 9 Nov; every picture somebody chose, the match stage too).** The picture fills a sunken hole and the shadow falls across it, moving with the light; initials and default icons are untouched. A `box-shadow` would be painted under an `<img>`, so a circle has it on an `::after` over the picture (`design.css`; a new picture box joins the two lists there). **A league's shield and a team's hexagon** are `TDC.leaguePic` and `TDC.teamPic`, the paths in `tdc.js`: an inset box-shadow can only follow a rounded rectangle, so the shadow is the page round the shape, blurred once and only moved (`.tdc-shade`, its own layer). A league or team with no picture shows the empty shape with its trophy or shield inside. Measured with the light moving, 120 pictures on one screen, software rendering: no inset 3.2% of a core, circles 4.4%, hexagons 17.8% (a fixtures page has about 32). The light rests after 30 s untouched.

**Left out, on purpose:** the stage (`#mv-stage` and all in it) and the slide to undo. The match page alone keeps the old drift and glow, for the stage (`page-light.js`), and the rule in `design.css` is written not to reach it. Compared element by element against the commit before on 7 Nov, signed in with a match drawn: no differences.

The entries below this section from before 7 Nov describe the earlier look where they mention outlines, green pills, upright steppers, the select pill or the date's three steppers.


| Layer | What belongs in it |
|---|---|
| `variables.css` | **Tokens only** — colour, space, radius, font, shadow |
| `global.css` | Element defaults |
| `nav.css` | The shell |
| `forms.css` | **The component layer** — buttons, fields, cards, tables, badges, panels, status lines |
| `design.css` | **The design** (7 Nov, UV): how every shared component looks, from the neumorphism sandbox: see "The design" below. Loaded after the component and control layers and before a page's own stylesheet. Tokens are `--nm-*`, at the end of `variables.css` |
| `controls.css` | **Custom controls** (24 Oct) — the visuals for `scripts/tdc-controls.js`, which builds them round an ordinary input marked `data-control="<kind>"` (or every one inside a `data-controls` container). Kinds: `stepper`, `date`, `select`, `slide` (26 Oct, explicit only) |
| `match.css` / `bracket.css` / `poster.css` / `league.css` | One page or one family each |

**`league.css` is new (23 Oct)**: the three transfer lists on `/leagues/manage/`, the rotation grid, and since 24 Oct the section line (copied from the profile page's inline style — a third user moves it to `forms.css`), the column tracks of `/leagues/`'s row table, the status colours (`.league-status-<key>`) and the search's filters and tiles. It is deliberately **not** in `forms.css` — one page's furniture should not become everybody's component. If the transfer boxes turn out to be worth having elsewhere, move them into `forms.css` rather than letting `league.css` grow.

**Every value in a page stylesheet should be a token.** If something needs a colour or a radius that is not in `variables.css`, the token is missing — add it there, do not hard-code it.

**What is chosen by hand, per theme (22 Oct):** `--color-primary`, `--color-on-primary`, `--bg-base`, `--bg-surface` (colour and opacity), `--text-primary`, `--text-muted`, `--border-color`, `--color-success`, `--color-warning`, `--color-error`, `--color-owner`, `--shadow-alpha`, `--scrim-alpha`, and the `--logo-*` set. Everything else (`--shadow-panel`, `--scrim`, `--hover-wash`, the `color-mix()` glows) is built from those. `--color-cream`, `--color-ink`, `--alpha-1` to `--alpha-4` and `--shadow-raised` were removed (nothing used them). UV edits them on `/sandbox/` and saves into the file.

UV asked on 20 Oct whether the site needed a design system. The answer reached was that the **tokens were already fine and the components were the gap**, which is why `forms.css` is the component layer. That answer is worth revisiting now that there are far more pages.

Fonts: **Rushford Clean** for display, **Selawik** for body, both self-hosted in `resources/fonts/`.

Branding: UV moved to **black elements with alpha** for shadows and gradients in the artwork. He now sets the alphas himself on `/sandbox/` and saves them; do not guess values.

**The logo files carry their own colours** (checked 3 Nov). Every live page shows a logo as an `<img>`, so it draws exactly what the file holds: `logo-primary-dark.svg` and `logo-mark-dark.svg` green #61ffad and cream #f4e8d2, the `-light` pair cream #f4e8d2 and navy #20333b, all with 32% flat shadows, 64% blurred shadows at 12.5% blur and the same gradient. The `--logo-*` variables in `variables.css` are read **only by `/sandbox/`**, which loads a file inline; since 3 Nov both themes' sets are the files' own values (the light set had been an early grey trial, #594f4f / #a8a7a7). They start doing something on the live site only once the logo goes inline (the row below). **The artwork follows the theme** (UV, 3 Nov; `docs/DECISIONS.md`): every logo and icon is placed twice, the dark file with `.for-dark` and the light with `.for-light`, and `global.css` hides the other theme's. Home page: `logo-primary-dark.svg` / `-light.svg`; nav and loading screen: `icon-primary.svg` / `logo-mark-light.svg`. A new logo anywhere does the same. **Inside an SVG `<use>` copy the rule does not reach** (a selector cannot see through it): there the image's `display` reads a custom property the theme flips, as the install drawing does (`--ins-show-dark` / `-light`). The install drawing and the phone's bar follow the theme too (3 Nov).

### Decisions already made — do not reopen without asking

- **Every field glows on hover (UV, 24 Oct)**, on every page: text boxes, number and date fields, text areas and selects, not checkboxes, radios or anything disabled. A field is a line, not a box, so the line glows (`--glow-line`: the underline lit green with a soft light below) rather than the rows' box glow (`--glow-primary`) appearing round it.
- **Scrollbars are a grey thumb and nothing else (UV, 24 Oct)**, site-wide in `global.css`: no track, no arrows, as Chrome draws them on a phone. Chrome, Edge and Safari use the `::-webkit-scrollbar` parts; Firefox gets `scrollbar-width: thin` and the same grey, kept behind `@supports not selector(::-webkit-scrollbar)` because Chrome ignores the parts once `scrollbar-color` is set. `--scrollbar-thumb` and `--scrollbar-size` in `variables.css`.
- **Anything that scrolls sideways fades at its edges (UV, 24 Oct)**, only on a side with more to scroll to: every `.table-scroll`, and `.scroll-x` for anything else (the league search tiles). A mask driven by a scroll-driven animation, so no wrapper or script; Firefox and older Safari show plain edges.
- **Every number field becomes a stepper (UV, 24 Oct)**: the number in the brand colour in a cream pill, a chevron above to go up and one below to go down. A chevron disappears at its limit and the pill shrinks with it, as in UV's three pictures. Hold a chevron to keep going. **A changing number rolls** (UV, 24 Oct): the new one slides in and pulls the old one out, upwards when it goes up and downwards when it goes down; not while typing, and not when the device asks for less motion. **Its label and hint sit to its right**, on the bottom line (UV, 24 Oct; the script marks the field `.field-beside`). **Every such control lines up down the page** (UV, 24 Oct, replacing "each pair centred on its own", which zigzagged): two equal columns, the control's right edge on the page's centre line, the words to the right of it. A control wider than half the row (a date on a narrow phone) takes what it needs and the line moves for that row only, so the two dates of a pair still line up with each other. Switches and rings sit the same way. **Clicking the number types one** (UV, 24 Oct): it glows while being edited, the number is selected so typing replaces it, letters are refused, a phone shows the number pad, and Enter or leaving it commits it, pulled into range (Escape undoes). The arrow keys still work. **Site-wide since 24 Oct** (UV): every number field. A stepper widens for a longer number (its max, or what is in it) and draws a placeholder ("No limit", "Never") small enough to fit. how custom controls work is in `docs/DECISIONS.md` (24 Oct).
- **A date as three steppers (UV, 24 Oct)**: year, month and day pills, with the cream calendar button (the browser's own picker) and a cross under it (clears the date; hidden while empty) stacked to their **left**, and the label and hint to their right as for a stepper. Every date field, site-wide (Starts and Ends on the new-league and settings pages today). ## 3. Things that will cost you time if you do not know them

- **The service worker caches aggressively.** `?v={{ build.version }}` busts it on each build, but a stale install can sit on an old deploy through any number of browser reloads. When UV says a change has not appeared, suspect this first. **`_site/` being stale is the same trap** — on 21 Oct it was 27 hours behind `src/` and sent an investigation down the wrong road for half an hour.
- **A flex item with `min-width: 0` can collapse to nothing.** On 21 Oct `span.bracket-name` measured **0 × 20** on UV's screen — every player's name invisible, with the frame score left looking like the name. It was never reproduced: the DOM, the function's return value and all five stylesheets checked out, and a headless Chromium rendering the same markup against UV's own CSS gave the name 158–178 px every time. It was fixed **structurally** — the row is now a three-track grid, `auto 1fr auto`, because a `1fr` track cannot be squeezed away by what sits beside it. Prefer grid with explicit tracks over a flex line wherever an element must never vanish.
- **The same trap caught `.list-row` on 22 Oct**, and that one *was* reproducible: `/leagues/fixtures/` put three `.btn-sm` controls and a `datetime-local` input in `.list-row-actions`, and at 420px "Charlie v Delta" came out one word per line with the buttons sitting over it. Fixed in the page's own markup by nesting a `.btn-row` (which wraps) **inside** `.list-row-main` rather than beside it, so the names always get the full width. **A fixed-width actions column beside text is the shape to distrust.** Caught by rendering it full-page at 420px, not by reading it.
- **A dropdown anchored to a mid-bar button will hang off the screen.** The notification tray was `position: absolute; right: 0` on its button, which on a 420px phone put a 22rem tray partly off the **left** edge; it was fixed to the viewport instead (22 Oct), and since 29 Oct it is in the menu. Caught by rendering it, not by reading it.
- **A `.row-table` row's line is drawn by `::after`, not its border** (24 Oct). The row has rounded corners for the hover glow and is pulled out by its own padding so its text lines up with the headings; a border would curve up at its ends and run wider than the section lines. Both were caught by rendering it.
- **A blur inside a blur shows nothing** (24 Oct). An element with `backdrop-filter` is a backdrop root, so a panel inside it with its own `backdrop-filter` blurs only that element, not the page: the notification tray and the profile panel sat inside the blurred nav bar and their blur did nothing. The bar's glass is now a `::before` layer behind it. It also stopped the bar being the containing block for its fixed children, which happened to make no difference to the tray (both are 60px from the top). Any new panel hung off a blurred surface needs the same. **The bar reaches up behind the notch or Dynamic Island** (UV, 25 Oct: that strip is part of the bar and hides with it). `viewport-fit=cover` in `layout.html` lets the page draw there, and the bar is `--nav-total` tall (`--nav-height` 60px plus `--nav-top`, the safe-area inset, 0 off a phone), its buttons in the 60px below the strip. **Everything that clears the nav uses `--nav-total`, never 60px**: the body, the menu, the tray, the match page's stage, panel and overlay, the home page, the sandbox. The body also keeps clear of the home bar (`safe-area-inset-bottom`), and the match stage subtracts it. The bar's colour stays on the bar itself and only the blur is on the layer. **The phone's own status bar is the page's background** (UV, 29 Oct): `apple-mobile-web-app-status-bar-style` is `black-translucent`, so iOS draws the page under it, and `theme-color` (`layout.html`) and the manifest's `theme_color` and `background_color` are `--bg-base`, #202020, for Android, desktop and the installed app's splash. They are literal values, not the token, so a change to `--bg-base` must be copied to all three (and to the three forwarding pages under `/leagues/` that have their own `<head>`). **The bar follows the theme since 3 Nov (UV):** `prefs.js` sets `theme-color` to the theme's own `--bg-base` on load and on every toggle, and in the light theme asks iOS for dark status-bar text (`apple-mobile-web-app-status-bar-style` `default`), since white on cream cannot be read. iOS reads that when an installed app opens, so it takes effect from the next launch, and whether iOS honours a tag set by script that early is **unconfirmed until tried on an iPhone**. The forwarding pages do the same in one line (#f4e8d2 written in, as they load no stylesheet). The manifest stays #202020: it is fixed at install.
- **`font: inherit` on a button resets more than you mean.** Stripping a button back to looking like text also drops `font-style` and `color`, which silently undid a `.pending` modifier. Equal specificity, later rule wins.
- **`<summary>` text and button labels are upper-cased by CSS.** `innerText` comes back in capitals, which will quietly fail any test that compares it to what the markup says. This has now cost four test runs across two days — compare case-insensitively.
- **The primary context is a phone at the bar**, in a hurry, one-handed, often with poor signal. Tap targets matter more than density. The TD is standing up. **That is not an argument against a desktop layout** — see the PC job in §2 — it is an argument for the phone staying the one that is checked first.
- **`TDCMatchDef` in `scripts/match-settings.js` is the one place a match setting is defined** — label, type, options, defaults. The match panel, the create page and the poster text all generate from it. Adding a setting is one edit there, never two. It now also holds `LEAGUE_DEFAULT_RULES` (what a team night starts from) and `LEAGUE_GROUPS` (a settings group deliberately outside `GROUPS`, so only the league pages render it). **Build a group's controls with `TDCMatchDef.layout(defs, make)`**, never `defs.map(make)`, or the rows and lines (`row`, `rule`) are lost.
- Load order matters: `match-settings.js` before `match.js` and before `match-new.js`.
- **An Inkscape SVG's ids are generic and its meaningful names are `inkscape:label`.** Code that adjusts the logo finds parts by label (`sha_*`, `col_m_*`, `col_l_*`, `blu_*`, `gra_m_all`), never by id.
- **A bigger Inkscape blur needs a bigger filter region.** The saved `x`, `y`, `width` and `height` on a blur filter are sized to the blur at the time, so raising the blur without scaling them clips the shadow at the edge.
- **`device_commit_files` can add a C2PA content-credentials block to an SVG** written to the repo (seen 22 Oct, about 7 KB inside a `<metadata>` element). Harmless to rendering, but it is not in UV's original file.
- **Saving from `/sandbox/` writes to `variables.css` behind your back.** The page patches the file UV chooses, so before editing `variables.css` yourself, stage it fresh: the on-disk copy may be newer than yours. The patcher keeps line endings, indentation and trailing comments, and only touches the values it was given.
- **Logo values saved as `--logo-*` are a whole set per theme.** A theme with none inherits the dark (`:root`) set. SVG attributes that CSS cannot reach (the blur's `stdDeviation` and the gradient stop `offset`) must be set by script from the variables; the sandbox's `logo` module is the working example.
- **Testing animations in headless Chrome needs a real clock** (24 Oct). `--virtual-time-budget` freezes CSS transitions and Web Animations part-way (a rolled number vanishes, the green pill never moves), which looks exactly like a bug. Drive Chrome over the DevTools protocol (`--remote-debugging-port`, `Emulation.setDeviceMetricsOverride` for a true 420px, which a headless window will not go below 500px to give) and wait instead. A headless `--screenshot` at `--window-size=420` silently crops a 500px page.
- **A transition switched off by removing a class must say `transition-property: none` in the base rule** (24 Oct). The select pill's slide was "on" by a class that set the property, with the duration set inline by the script; with the class off, the property fell back to its default, `all`, so the jumps meant to be instant animated too. The slide then started from the wrong place: it looked fine going right and jumped going left. Found only by sampling the pill's position every frame; one screenshot shows nothing.
- **A press can end on a different element from the one it started on** (24 Oct). The ruleset pages rebuild their form on every change, so a stepper's chevron is replaced under the finger and the release lands on the new one. The hold-to-repeat timer listened for the release on its own button only, so the thrown-away stepper kept stepping unseen to its limit, where it recorded its field's chevron as gone, and the next rebuild drew the real one in. A press now ends on a release anywhere (`window`), a detached control stops, and only a control on the page may record what its icons show. A scripted test that releases on the same element cannot catch this: release on the new one.
