# File map (src/)

> Moved verbatim from `CLAUDE.md` on 23 Oct 2026. Where each page, script and stylesheet lives. Originally headed *- `_includes/layout.html` is the shared shell (head, PWA meta, nav, Supabase library + client, `tdc.js`, `forms.css`, per-page scripts, SW registration).*.

  - Pages opt in with front matter: `layout: layout.html`, `title`, `description`, optional `extraScripts: [...]` (loaded after `supabaseClient.js`), optional `extraStyles: [...]` (extra stylesheets, with the build stamp), optional `hideNav: true`.
- `_includes/nav.html` + `scripts/nav.js` + `stylesheets/nav.css` make up the shared nav. Nav items live in `_data/navLinks.json`.
  - **Reload button, shown only when running installed** (`display-mode: standalone`, or `navigator.standalone` on older iOS). An installed app has no address bar, so a page that has gone stale — a live page whose socket dropped, or one opened before the last deploy — has no way out; pull-to-refresh is not reliable either, because the match page's own scrolling swallows it. In a browser the chrome already has one, so it stays hidden. It asks the service worker to check for a new version first, which also drags a stale install onto the current deploy, but that check can never hold the reload up: both the lookup and the update are raced against a 1.5-second timeout so a slow or missing worker cannot leave somebody pressing a dead button.
  - The account button shows the signed-in player's profile picture when they have one, and the generic icon otherwise. `nav.js` swaps it only once the image has loaded, and falls back to the icon if the file is missing, so a stale path never leaves a broken picture in the nav. The profile page fires a `tdc:avatar-changed` window event after a save or a removal so the nav follows without a reload.
  - Note: `src/navLinks.json` is a stray duplicate and can be removed. **Still there as of 21 Oct** — Claude writes files through the device bridge and cannot delete one, so this needs `git rm` by hand.

Every page that saves uses it (league manage, fixtures, season, join, card; tournament manage, bracket, poster; the profile's notification switches), and `match.js` queues through `TDC.queued` with its own card-version handling. Do not add a "busy" flag that drops a click.
- **`scripts/league-nav.js`** (24 Oct, UV): **a league's pages in one horizontal pill** at the top of the season, fixtures, manage, settings and card pages, styled in `forms.css` (`.league-nav`) like a select pill, the current page in green: Season · Fixtures · Run it · Settings · New season. - **`scripts/ring-status.js` + `stylesheets/status.css`** (24 Oct): **UV's ring status design**, ported from his demo without redesign: `TDCRing.RingStatus` (a ring whose four dots orbit while loading, then peel off on curved paths and draw an icon stroke by stroke), its 16 icons (18 since 24 Oct: `calendar` and `minus` added for the fixtures' buttons) and `TDCRing.svg()`. Changes from the demo: only the icons a control uses get paths (a table of Paid ticks would otherwise carry 16 icons each), the fill and ink colour code is gone (the fill was always transparent), `labels` sets the live text, `onDone` reports the end, `onProgress` follows the dots along their whole paths (the curve off the ring as well as the stroke, so a switch's knob sets off the moment the load is done rather than lurching once strokes begin), and `resolve(target, { together })` sends every dot at once from wherever it is at the load time (each to the stroke start nearest it, dot 0 to stroke 0), `{ now }` the same straight away, instead of each waiting for its own exit point. The site always uses one or the other: form boxes and newly shown ones `together`, saving ones `now` once the network is quiet. Loaded on every page before `tdc-controls.js`, which builds the checkboxes from it. **`TDCNet`** in `supabaseClient.js`: the client is created with a fetch that counts what is in flight, and `rpc` / `from` count the moment a page asks (the fetch starts a moment later, after the sign-in token); `TDCNet.quiet()` resolves once nothing has been in flight for 50 ms. Counting only.
- **`scripts/tdc-controls.js` + `stylesheets/controls.css`** (24 Oct): **custom controls**, loaded on every page by `layout.html` (the script straight after `tdc.js`, the stylesheet after `forms.css`). A control is the page's own form element with `data-control="<kind>"`, or any element a kind takes inside a container with `data-controls="<kinds>"` (`data-control="none"` opts one out); the script builds the furniture round it once every script has run, and a `MutationObserver` picks up anything rendered later. The input stays the real one, so `.value`, `input` and `change` work as before, and a button press fires both events. Setting `.value` from a script also updates the control. A new kind is one `TDCControls.define(name, enhance, autoSelector)` in that file; an unknown kind is reported with `TDC.error`. On every page since 24 Oct: `layout.html` puts `data-controls="stepper date select"` on `<body>`, and each kind's auto selector leaves out anything inside a table. Fields kept native carry `data-control="none"` (`league-card.js` position and reserve pickers, `tournament-bracket.js` swap picker and score boxes). Every `data-controls` container round a field counts, nearest first. Kinds (and `switch` / `ring` for checkboxes, below): **`stepper`** (an `<input type="number">` with `min`/`max`: a pill with a chevron above and below, each hidden at its limit, hold to repeat; the number sits in a clipping `.tdc-stepper-window` and a change rolls through it with the Web Animations API, the old number carried out by a `.tdc-stepper-ghost`; click the number to type, refused letters, clamped on commit; the pill widens by `--chars` for a longer number; its number rules carry three classes' weight so `match.css`'s `.set-row input[type="number"]` cannot reach in; **`data-stepper="across"`** (24 Oct) lays it on its side, `.is-across`: down on the left, up on the right, the number rolling sideways, small (`--stepper-across-number`), a hidden chevron keeping its place, not moved beside a label; a row of them is a `.stepper-row`, which scrolls sideways — a fixture's table numbers), **`date`** (an `<input type="date">` shown as three steppers, with a calendar button that calls `showPicker()` on the real input, which sits invisibly under it, and a clear button, stacked to their left in `.tdc-date-tools`; the parts' own events stop at the control, so the page hears only whole dates), **`select`** (a `<select>` shown as a horizontal pill of option buttons, arrows at the ends; the green pill is a `.tdc-select-thumb` under the options that slides by a transition; a page that rebuilds the select hands the slide on through `thumbWas`, keyed by the select's id, and a `ResizeObserver` puts the pill back without sliding when the width changes (a folded group opening); the real select stays inside, invisible but focusable, so Tab and the arrow keys still work; not taken automatically inside a table). A stepper or date whose parent is a `.field` marks it `.field-beside`, and `controls.css` lays it out as a grid: the control centred on the left, the label and hint on the right on the bottom line. A select pill is centred in its field. **`switch`** (every checkbox) and **`ring`** (`data-control="ring"`): the checkbox stays the real one, invisible over the drawing and focusable; a change starts the orbit at once and registers the control in `liveChecks` (by id, or data-action with data-entrant / data-player) so a page that rebuilds hands it to the new checkbox; once the page's handler has run, if it asked the database anything the answer is drawn at `TDCNet.quiet()` (20 s at most), otherwise at once. `drawIcon()` draws a control's icons in and out (every SVG part with `pathLength="100"`), in `--ring-draw`; `iconSeen` remembers each by `data-icon-key` (the field's id and its role), so a page's rebuild does not redraw icons that were already showing. **`morph()`**: a capture listener snapshots every keyed `.field` and `details.set-group` (by control id, by `data-group`) as a change starts; the body's `MutationObserver` compares each batch of DOM changes with the last picture while the change is being handled (the browser hands changes over between listeners, so a control's own change can come before the page's rebuild). New items grow in (`grow()`: height, margins and opacity, overflow hidden) and new switches and rings `appear()`; removed ones are put back, still whole, after the field above them (or its fading copy), marked `.tdc-gone` and inert, and shrink out. An item inside a section that came or went moves with the section; a `.field-row` (`TDCMatchDef.layout`) is an item too, keyed by its section and `data-row`, so a row comes and goes whole. **`fold()`**: a click on a `details.set-group`'s summary is taken over, and the section grows while its settings fade in (icons redrawn, switches `appear()`) or shrinks while they fade out, in `--control-reveal`; a second tap turns it round. A click is never ignored, even mid-animation. A box that saves orbits at the normal speed until `TDCNet.quiet()`, then resolves `now`: the drawing starts the moment the call is back, however short. A newly shown switch or ring orbits for `--control-reveal`, then draws. The field glow in `forms.css` skips a field that has become a control (`[data-control-ready="yes"]`; one kept native still glows); the pill glows instead, on hover and while focused. Sizes and the line colour are tokens (below), all editable on `/sandbox/`.
- **Fonts** live in `src/resources/fonts/` (published automatically by the existing `resources` passthrough). Two families, declared in `global.css` and used via the `--font-display` / `--font-body` tokens in `variables.css`:
  - **Rushford Clean** (headings only, `h1`-`h4`): UV's own licensed font, shipped as woff2 -> woff -> otf. It's an all-caps face with no em dash or middle dot, so keep those out of headings. `size-adjust: 150%` on its `@font-face` is the single knob for how large headings read; change that number rather than every heading's font-size.
  - **Selawik** (body text): Microsoft's open-source (SIL OFL) metric-compatible replacement for Segoe UI, which is proprietary and can't legally be served as a web font. `--font-body` lists `"Segoe UI"` first so Windows uses its locally installed copy; every other device downloads Selawik, which has identical metrics (2048 upem, 1434 cap height), so both look the same. Licence kept at `src/resources/fonts/selawik-LICENSE.txt` — it must stay with the font files.
- **The mockup match is gone (21 Oct).** `/match/` with no id used to render a hand-written league night — seven invented players, four frames — and `match.js` carried it as the initial value of `MATCH` and `PLAYERS`. It was the quickest way to work on the layout before there was anything real, and it had stopped being that. Removed: the seed data, the nav link to `/match/`, and the three paths that fell back to drawing it (no id, a malformed id, a failed load) — that last one mattered, because a match that failed to load showed somebody a fictional league night instead of saying it could not find theirs. `MATCH` is now null until a match loads and `canEdit` defaults to false rather than true. `PLAYERS`, `player()` and `names()` stay: the real rendering path uses them and `loadMatch` fills them.
- **The match settings panel is a form and is laid out like every other form on the site** (21 Oct): label above, full-width underlined field, hint below, using deliberately the same numbers as `.field` in `forms.css` rather than numbers that merely look similar. It used to be a two-column list with the control right-aligned beside its label, which read as a different product the moment you opened it next to the account pages. `.panel-block h2` matches `.tdc-card h2` for the same reason. The class names in `match.js` are untouched, so this was a CSS-only change; `.set-row.stack` is left as a no-op because `match.js` still emits it.
- `stylesheets/variables.css` is the **token layer**, and nothing else should hold a raw colour, radius or spacing value.
  - Brand: `--color-primary` (teal) and `--color-on-primary`, which is what sits on top of a teal fill and differs per theme: the dark theme's teal needs dark text, the light theme's deepened teal needs cream. (`--color-cream` and `--color-ink` were removed on 22 Oct: nothing used them.)
  - **`--scrollbar-thumb`, `--scrollbar-size`** (24 Oct): the site-wide scrollbar (`global.css`), a grey thumb and nothing else.
  - **`--control-line`** (24 Oct): cream (`--text-primary`), the outline and chevrons of a custom control and the calendar icon on every date field (`global.css`). With it, the controls' sizes: `--control-border`, `--chevron-size`, `--chevron-stroke`, `--stepper-width`, `--stepper-number`, `--date-year-width`, `--date-part-width`, `--date-number`, `--select-text`, and `--control-motion` (how long a roll or a slide takes; the script reads it too, and 0 turns both off). All in the sandbox's Controls group (`--scrollbar-size` is under Lines), a new `size` kind there: a slider with its own range and unit. `--ring-size`, `--ring-size-table`, `--switch-height`, `--switch-width`, `--ring-load` (1 s), `--ring-draw` (0.4 s), `--ring-fade` (0.1 s), `--ring-spin` (2, the dots' orbit speed times the demo's; `load({ spin })`): the ring and switch, in the sandbox's Ring and switch group. `--control-reveal` (0.35 s): fields fading in and out, in the sandbox's Controls group. `--icon-calendar` is the native date-and-time field's calendar (`global.css`); the date control's icons are drawn SVG now, and `--icon-clear` is gone.
  - **`--glow-line`** (24 Oct): the same glow for a field, which is a line: every text box, text area and select on hover.
  - **`--glow-primary`** (24 Oct): the hover glow on anything you open (`.row-table-row`, `.match-card`, the league search tiles), built from `--color-primary`.
  - Depth (22 Oct, simplified): **two chosen values per theme**, `--shadow-alpha` (floating panels and menus) and `--scrim-alpha` (the dim behind a slide-over panel), both black at that opacity, as the artwork builds its shadows. `--shadow-panel`, `--scrim` and `--hover-wash` are **built from them** (`--hover-wash` is the text colour at 6 %, so it follows the theme). The old `--alpha-1` to `--alpha-4` and `--shadow-raised` were removed; the only users were the panel shadow and the scrim.
  - **What is specified per theme** (and so what `/sandbox/` edits): `--color-primary`, `--color-on-primary`, `--bg-base`, `--bg-surface` (colour and opacity) with `--surface-blur` (px, the blur behind any translucent surface: used by the nav, menu and dropdown in `nav.css` and by `.panel`, `.tile-link`, `.match-card`, `.code-item` in `forms.css`; other `--bg-surface` users in `match.css`, `poster.css`, `bracket.css` and the board do not blur yet), `--text-primary`, `--text-muted`, `--border-color`, `--color-success`, `--color-warning`, `--color-error`, `--color-owner`, `--shadow-alpha`, `--scrim-alpha`; plus the `--logo-*` set below once saved. Colours mixed from these with `color-mix()` (tile glows, badge washes) follow automatically.
  - Logo (set from `/sandbox/`, added to `variables.css` the first time one is saved): `--logo-shadow-alpha`, `--logo-primary`, `--logo-light`, `--logo-blur-alpha`, `--logo-blur` (Inkscape %, 10 to 15), `--logo-grad-start`, `--logo-grad-mid`, `--logo-grad-end`, `--logo-grad-offset`. A theme with none of its own inherits the `:root` (dark) values.
  - Space and shape: `--space-1`-`--space-7`, `--radius-sm/md/lg/pill/round`, `--nav-height`.
  - The light theme is a cream page (`--bg-base: #f4e8d2`), not a grey one, and its teal, success, warning, error and owner colours are all deepened so they still pass contrast on cream.

    - **Logo controls.** With the SVG rendered inline, controls adjust the logo's parts, **found by their Inkscape labels, not their ids** (Inkscape's ids are generic): `sha_*` flat shadows (black, opacity X, 32 by default), `col_m_*` primary and `col_l_*` light (any colour, no alpha), `blu_*` blurred shadows (black, opacity X, 64 by default, blur 10 to 15 %, 12.5 by default) and `gra_m_all` (black, opacity at each of three stops, and the middle stop's offset). **The logo is driven by CSS variables** (`fill: var(--logo-primary)`, `fill-opacity: var(--logo-shadow-alpha)`, `stop-opacity: var(--logo-grad-mid)` ...), as the live site's inline logo will be; only the two things CSS cannot reach, the blur amount and the gradient offset (SVG attributes), are set by script from the same variables. Until a value is saved the variable starts at what the SVG file says (supplied as an inline seed, not a draft). **Each control sets only its own variable** (a range input snaps to its step and would otherwise quietly round the others). Saving any logo value writes the **whole `--logo-*` set** for that theme, so the file never holds half a logo. The blur % is a multiplier on the saved filter: Inkscape's deviation is proportional to the percentage for a given shape, so 12.5 to 15 is x1.2 on `stdDeviation`. **The filter region is scaled too**, because Inkscape sizes it to the blur at the time and a larger blur would clip at the edge. The logo's part names are the contract: a part renamed or added under one of those prefixes is picked up without a code change.

- `sw.js` + `site.webmanifest` make the PWA installable (iOS confirmed). The service worker caches only its `CORE_ASSETS` list (cache-first); pages are network-first and always revalidated with the server (`cache: 'no-cache'`), so a deploy shows on the next page load.
  - **`CACHE_NAME` carries the build stamp and no longer needs bumping by hand.** `layout.html` registers `/sw.js?v={{ build.version }}` and the worker reads that stamp into its cache name, so every deploy is a new cache and the `activate` handler deletes the previous one. Before this, a changed logo or icon stayed cached on every device that already had the old one, because `CORE_ASSETS` is served cache-first and the logo URL carries no stamp.
- **Cache-busting:** GitHub Pages lets browsers reuse CSS/JS for 10 minutes. `layout.html` adds `?v={{ build.version }}` (from `_data/build.js`, new on every build) to every stylesheet and script, including `extraScripts`, so each deploy's pages load that deploy's files. New stylesheets/scripts must be linked through `layout.html` or `extraScripts` to get the stamp.
